HMW 2 – Zeek Log Analysis

Before You Begin

For this lab, you need a working Ubuntu virtual machine with Internet access and a terminal. This exercise uses Zeek to analyze a packet capture (PCAP) file and generate JSON-formatted network logs.

Compatibility note: The original Lab 3 installation instructions use the Zeek repository for Ubuntu 22.04. If you use another Ubuntu release, select the corresponding supported Zeek repository rather than using the 22.04 repository unchanged.

Part 1 – Installing Zeek

1. Install Prerequisites

Open a terminal and run:

sudo apt-get install -y curl gnupg2 jq wget

2. Add the Zeek Repository Signing Key

The original lab provides this command (for Ubuntu 22.04):

curl -fsSL https://download.opensuse.org/repositories/security:zeek/xUbuntu_22.04/Release.key | sudo gpg --dearmor -o /etc/apt/trusted.gpg.d/security_zeek.gpg

3. Add the Zeek Package Repository

echo 'deb http://download.opensuse.org/repositories/security:/zeek/xUbuntu_22.04/ /' | sudo tee /etc/apt/sources.list.d/security:zeek.list

4. Update Package Lists

sudo apt-get update

5. Install Zeek

sudo apt-get install zeek

During installation, you may see Postfix Configuration screens. The following screenshots from the original lab illustrate these prompts. The exact screens may vary by Ubuntu version and installed packages.

6. Verify the Installation

Run:

/opt/zeek/bin/zeek --version

If the command is unavailable, check the installation path for your Zeek package.

Part 2 – Generating Zeek Logs from a PCAP File

7. Navigate to the Desktop

cd ~/Desktop

8. Download the Packet Capture

wget http://cs.ucmo.edu/~aksoy/teaching/cybr5940/SkypeIRC.cap

Verify that SkypeIRC.cap was downloaded.

9. Create a Directory for Zeek Logs

mkdir zeek_logs

10. Enter the Directory

cd zeek_logs

11. Analyze the Packet Capture with Zeek

/opt/zeek/bin/zeek -r ~/Desktop/SkypeIRC.cap -C LogAscii::use_json=T

The -r option reads packets from the capture file. The -C option disables checksum validation, and LogAscii::use_json=T requests JSON-formatted logs.

12. Examine the Generated Logs

List the files created by Zeek:

ls -l

The logs produced depend on the protocols and events observed in the capture.

Part 4 – Analyzing Network Traffic with Linux Commands

In this part, you will investigate the traffic recorded in conn.log. You do not need advanced jq knowledge. Use jq to extract fields from JSON records, then combine it with familiar Linux commands such as sort, uniq, head, grep, cut, and tr. All exercises can be completed with the commands introduced below.

14. Extract Fields from JSON

For example, the following command prints the source IP address (id.orig_h) from every connection:

jq -r '."id.orig_h"' conn.log

The -r option outputs plain text instead of quoted JSON strings. To display the most frequently occurring source IP addresses, run:

jq -r '."id.orig_h"' conn.log | sort | uniq -c | sort -nr | head

Here, sort groups matching IP addresses, uniq -c counts occurrences, sort -nr orders results from largest to smallest, and head displays the first results. This counts connection records, not packets.

Useful fields in conn.log include:

Field Meaning
id.orig_h Originator (source) IP address
id.resp_h Responder (destination) IP address
id.resp_p Destination port
proto Transport protocol
orig_pkts Packets sent by the originator in a connection
resp_pkts Packets sent by the responder in a connection
orig_bytes Originator payload bytes, when available
resp_bytes Responder payload bytes, when available

Important: Zeek’s originator and responder are roles within a connection. The originator is not necessarily a malicious host. Also, a host can appear as the originator in one connection and the responder in another.

15. Exercises

Use conn.log and command pipelines built from jq, grep, cut, tr, sort, uniq, uniq -c, and head. You may use sort -n, sort -r, or sort -nr to sort numeric results. You do not need awk, scripts, loops, or advanced jq programming.

For each exercise, include the command(s) you used, readable output, and a one- or two-sentence explanation.

  1. Most active source IP: Which originator (id.orig_h) appears in the most connection records? Report its IP address and number of connections.
  2. Most contacted destination IP: Which responder (id.resp_h) appears in the most connection records? Report its IP address and number of connections.
  3. Top five destination ports: Find the five most frequently used destination ports (id.resp_p). Show the port numbers and their connection counts.
  4. Protocol distribution: Count how many connection records use each protocol (proto). Which protocol appears most often?
  5. Connections involving a selected IP: Choose an IP from Exercise 1 or 2. Find records in which it appears as the originator and records in which it appears as the responder. Report the two counts separately.
  6. Largest packet count in a single connection (originator): Identify the connection record with the highest orig_pkts value. Report its originator IP and packet count. This is the number of packets in one connection, not the total across all connections.
  7. Largest packet count in a single connection (responder): Identify the connection record with the highest resp_pkts value. Report its responder IP and packet count. Again, consider one connection record, not an IP-wide total.
  8. Interpretation: Compare the IPs from Exercises 1 and 6, and from Exercises 2 and 7. Explain why an IP with many connections may not appear in the connection with the largest packet count.

Command Hints

To extract a single field, use the following pattern (replace the field name as needed):

jq -r '."id.orig_h"' conn.log

To count repeated values, combine sort, uniq -c, and sort -nr:

jq -r '."id.orig_h"' conn.log | sort | uniq -c | sort -nr | head

For Exercises 6 and 7, you can extract two fields on each line using jq and then sort by the numeric packet-count column:

jq -r '[."id.orig_h", (.orig_pkts // 0)] | @tsv' conn.log | sort -k2,2nr | head

The output contains an IP address followed by the number of packets in that individual connection. For Exercise 7, change the fields to id.resp_h and resp_pkts. The // 0 portion treats missing packet counts as zero.

You can use grep to filter lines containing a chosen IP, and cut or tr to separate or reformat text as needed.

Important distinction: uniq -c counts matching lines (for example, connection records). It does not add packet counts. You are not required to calculate total packets per IP across multiple connections in this homework.
