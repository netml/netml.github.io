Homework 3 – NetFlow

Objective

In this homework, you will install nfdump, convert a packet capture (PCAP) into flow records using nfpcapd, and explore network traffic using nfdump. You will practice interpreting flow fields, changing output formats, and applying flow filters.

Environment: Ubuntu Linux. Commands may differ across nfdump releases. If an option is unavailable, consult nfpcapd -h or nfdump -h and document the version used.

Part 1 – Install and verify the tools

1. Install nfdump from the Ubuntu repository

sudo apt update
sudo apt install -y nfdump

There is no need to clone or compile the source code for this assignment.

2. Verify installation and PCAP conversion support

nfdump -V
command -v nfpcapd
nfpcapd -h

Important: Ubuntu package versions differ. If nfpcapd is missing, or its help output does not support reading a PCAP file (-r), contact your instructor before proceeding. Do not substitute an unverified installation procedure.

Part 2 – Convert a PCAP to flow records

3. Return to the Desktop and download a sample capture

cd ~/Desktop
wget -O SkypeIRC.cap \
  'https://gitlab.com/wireshark/wireshark/-/wikis/uploads/__moin_import__/attachments/SampleCaptures/SkypeIRC.cap'

Note: If the sample-capture link has moved, obtain the SkypeIRC.cap capture from the Wireshark SampleCaptures collection and save it to ~/Desktop.

4. Create a directory for flow records

mkdir -p netflow

5. Convert the capture

nfpcapd -r SkypeIRC.cap -S 1 -z -l ./netflow

Check that the netflow directory contains generated files:

ls -lh ./netflow

Version check: Confirm the meaning and availability of -r, -S, -z, and -l with nfpcapd -h. If your installed version does not support these options, ask your instructor for the compatible command. The capture and output paths must match your files and directories.

Part 3 – Explore NetFlow records

6. Display records in different formats

Run each command and compare the information displayed.

a. Default output

nfdump -R ./netflow | head

b. Line format

nfdump -R ./netflow -o line | head

c. Long format

nfdump -R ./netflow -o long | head

d. Extended format

nfdump -R ./netflow -o extended | head

e. Custom output (timestamps)

nfdump -R ./netflow -o 'fmt:%ts' | head

For each format, identify the fields you can see, including source/destination addresses, ports, protocol, packets, bytes, and timestamps where available.

7. Filter flow records

nfdump uses its own flow-filter expression language, not the full Berkeley Packet Filter (BPF) language used by tools such as tcpdump.

a. Traffic involving port 53

nfdump -R ./netflow 'port 53'

b. TCP traffic

nfdump -R ./netflow 'proto tcp'

c. UDP traffic

nfdump -R ./netflow 'proto udp'

A filter may return no records if the selected traffic type is absent from the capture. An empty result is not necessarily a command failure.

8. Summarize traffic

a. Top 10 source IP addresses by bytes

nfdump -R ./netflow -s srcip/bytes -n 10

b. Top 10 destination IP addresses by bytes

nfdump -R ./netflow -s dstip/bytes -n 10

c. Top 10 destination ports by flow count

nfdump -R ./netflow -s dstport/flows -n 10

Part 4 – Questions (100 points)

Submit a single PDF containing your answers, the commands you used, and relevant screenshots or excerpts of command output. Explain findings in your own words.

  1. Installation verification (10 points): Report your nfdump and nfpcapd versions and provide evidence that the tools run successfully.
  2. Packet versus flow records (15 points): Explain the difference between a packet capture and a NetFlow record. Identify at least four fields found in the flow output and explain what they mean.
  3. Output formats (15 points): Compare line, long, and extended output. Which format is most useful for investigating a specific connection, and why?
  4. Protocol analysis (15 points): Determine which transport protocols appear in your converted capture. Provide the filter commands and supporting output.
  5. Port filtering (10 points): Run the port 53 filter. Explain what the result indicates. If there are no matches, explain why this is a valid finding and identify another port present in your data.
  6. Top talkers (15 points): Identify the leading source and destination IP addresses by byte count. Report the values and explain what the rankings tell you about the capture.
  7. Destination ports (10 points): Identify the most common destination ports by flow count. Discuss what services, if any, those ports typically represent; distinguish likely services from confirmed application behavior.
  8. Traffic filtering (10 points): Using nfdump, identify the source IP address that generated the most traffic in terms of bytes. Then filter the NetFlow records to display only traffic originating from that IP address. Provide the commands used and screenshots of the results.
